# Pane IA rethink: one stack, todos vs reminders (2026-10-02)

> Update: after trying both, the pane copies `mokkan ui`'s look: the header with credits and sync state, `Stack │ Done`, a `▸` pointer and bold for the selected row (no inverted background), and every key in a dot-separated footer (no `m`/more toggle).

Source: `/impeccable critique` of `claude-plugin/hooks/pane.tsx` (18/40), snapshot in
`.impeccable/critique/`. Decisions by the user: one stack + done; done and ack stay as main
keys, pop/dequeue go behind `m` with confirms that name the target; **simple todos and
reminders must read as different things**; the pane's keymap is canonical and `mokkan ui`
(the TUI) changes to match it.

## Model

- **Todo**: a reminder with `due_at === null` (made by `push`). A note on the stack.
- **Reminder**: a reminder with `due_at` set (made by `in`, or `t` on a todo). Time-bound.
- Both share the lifecycle `scheduled → due → delivered → acknowledged → done`.

## Views

Two views, switched with `s` (the TUI also accepts Tab):

- **stack**: every open reminder (`list --all`), in stack order, top first. Todos and
  reminders are interleaved; the kind is carried by glyph and time column, not by a tab.
- **done**: finished reminders (`done`), newest first. Pressing `a` on one reopens it.

Tab row: `[stack 4]  done 2` on the left, sync state on the right: `synced 12s` (dim),
`syncing…` (dim), `offline · 3m old` (yellow). Offline never wipes the list: keep the last
good data and mark it stale. Only a real logged-out state clears it.

## Rows

```
▸ □ 1: renew the TLS cert
      todo · pushed 3h ago · seen 1h ago
  ● 2: call the bank                overdue 40m
  ◷ 3: ask Maria re notes           Wed 17:00
  ○ 4: water the plants             2h ago
```

Glyph column. The shape gives the kind, and the variant gives the state:

| Kind | State | Glyph | Style |
|---|---|---|---|
| todo | any open state | `□` | normal; dim once acknowledged |
| reminder | scheduled (future) | `◷` | dim |
| reminder | due (fired, not yet shown/acked) | `●` | yellow |
| reminder | delivered (shown, awaiting ack) | `○` | normal |
| reminder | acknowledged | `·` | dim |
| either | done (done view) | `✓` | dim |

A todo never shows yellow. Yellow means "a timed reminder needs you", and nothing else.

Time column (reminders only; todos have none). Right-aligned and always prefixed so the
direction is never ambiguous:

- `due_at` in the future: `in 40m` (under 60 min), `17:00` (today), `Wed 17:00` (within
  7 days), `12 Oct` (later). Dim.
- `due_at` past and state `due`: `overdue 40m` / `overdue 3h` / `overdue 2d`, in red.
- `due_at` past and delivered/acknowledged: `40m ago` / `3h ago` / `2d ago`, dim.

Detail line: only under the selected row, dim, indented under the text:

- todo: `todo · pushed 3h ago` + ` · seen 1h ago` (delivered_at) + ` · acked` (acknowledged_at)
- reminder: `reminder · pushed 3h ago` + the same seen/acked parts
- done view: `done 2h ago · pushed 1d ago`

This needs `created_at`, `delivered_at`, `acknowledged_at` and `done_at` carried through (the
CLI's `--json` already returns them).

Width: measure display width, not code points. Wide characters and emoji count 2, and
East-Asian-ambiguous glyphs count 1. Nothing may exceed the body width; rows truncate text
with `…` and never push the time column off.

## Keys (canonical; the TUI matches)

Main legend (always visible while focused):

| Key | Label | Action |
|---|---|---|
| `p` | `todo` | push a todo: field hint `text (1 credit)` |
| `i` | `remind` | schedule a reminder: field hint `2h call the bank (1 credit + 1 reserved)` |
| `e` | `edit` | edit the selected text (`every 3rd edit costs 1`) |
| `t` | `time` | set/clear the selected one's due time (`2h`, or `clear`); turns a todo into a reminder and back |
| `a` | `done` | toggle done on the selected one (in the done view: reopen) |
| `k` | `ack` | acknowledge the selected one |
| `s` | `view` | switch stack / done |
| `m` | `more` | show/hide the overflow row (the engine only takes digits and lowercase letters as hotkeys, so not `?`) |

Overflow row (`m`): `x: pop`, `d: dequeue`, `r: refresh`, `o: logout`, `c: close` (the TUI uses
`b: buy` and `q: quit` in place of close). `pop`, `dequeue` and `logout` confirm, and the
confirm names its target: `pop "call the bank"?  y: yes  n: no`. On an empty stack, pop and
dequeue answer `the stack is empty` and don't confirm.

Selection: arrows / Home / End in the TUI; in the pane the arrows scroll the engine's window, so Tab (the focus ring) and clicks select. The TUI drops `j`/`k` movement,
because `k` is now ack. Digits jump to a row and select it. Selecting never marks anything
done; only `a` does.

## Status, busy and errors

- The status line renders in **every** mode (normal, field, auth, confirm), directly above
  the field or legend. Errors start with `error: ` and are red; successes are dim. A message
  clears itself after 15 s or on the next action.
- When a field submit fails (bad duration, CLI error, short password), the field stays open
  with what was typed, and the error shows on the status line.
- **Busy**: from the moment an action is pressed until its CLI call returns, the pane is busy.
  The header shows the verb (`pushing…`, `popping…`) and all action keys are ignored. Confirms
  leave confirm mode immediately on `y`, so a second `y` can't run the action again.
- Overlapping refreshes: only the newest one's result is applied.

## Header and balance

`mokkan` left. Right: `42 credits` dim; under 10: `7 credits · low` yellow; 0 or below:
`0 credits · buy` red (pane: `mokkan buy` in a terminal; TUI: `b`). While busy the right side
shows the verb instead.

## Focus (pane only)

Unfocused (`e.props.isFocused === false`): no legend; one dim line `ctrl+x tab to act`. The
list and status still show. Focused: the full legend.

## Empty states

- stack, empty: `Nothing on the stack. p adds a todo, i a reminder.`
- done, empty: `Nothing finished yet.`
- logged out: `Not logged in.` then `l logs in, g registers.` (on surfaces without Input:
  `Log in from a terminal: mokkan login`).
